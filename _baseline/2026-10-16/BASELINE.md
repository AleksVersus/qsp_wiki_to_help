## Два эталона (оба — в этой папке)

- `golden/` + `m_golden.json` — закоммиченный `html_out` с ручными правками.
  Это **желаемый конечный артефакт**.
- `code_regen/` + `m_regen1.json` — выход `python to_chm_prepare.py` текущим кодом.
  Это **истина о поведении кода**; доказана детерминированность: повторный прогон
  (`m_regen2.json`) побайтово совпал с первым.
- `m_html_src.json` — манифест входов (`html_src`, 89 файлов). Любое изменение
  исходников после этой даты будет видно по расхождению с этим манифестом.

Манифесты: SHA256, относительные POSIX-пути, `.chm` исключены. Генератор/сравнение:
`python _baseline/make_manifest.py <папка> -o <файл.json>`.

## Правило приёмки для всех последующих фаз рефакторинга

После каждого изменения кода сборщика:

1. Пересобрать: `cd chm_prepare; python to_chm_prepare.py` (или новый CLI, когда появится);
2. `python _baseline/make_manifest.py html_out -o _tmp.json` и сравнить с `m_regen1.json`;
3. **Расхождения = регрессия**, если только они не задокументированы заранее в этом
   файле как намеренное изменение поведения;
4. Сверка с `m_golden.json` отдельно: разница golden↔regen остаётся ровно 2 файла,
   пока ассет-пайплайн и генератор hhk не починлены (это Фазы 6–7).
