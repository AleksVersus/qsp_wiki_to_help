# План рефакторинга qsp_wiki_to_help

> Черновой план. Код пока не изменяется. Контекст проекта и накопленные знания — в `handoff.md`.

## Цель

Реорганизовать разрозненные скрипты в Python-пакет с переиспользуемыми модулями:
убрать дублирование, зависимость от CWD и «магические» константы, разделить сетевой
код, код трансформации HTML и оркестрацию. Итог — единая точка входа
(`python -m qsp_help_builder <этап>`) и модули, которые можно переиспользовать
по отдельности (например, только генерацию hhc/hhk или только загрузчик вики).

## Текущее состояние (что рефакторим)

| Файл | Роль | Проблемы |
|---|---|---|
| `qsp_wiki_downloader/qsp_wiki_downloader.py` | краулинг wiki.qsp.org → `html_src/` | god-class: сеть + разбор HTML + именование файлов + сохранение + лог; путь `..\html_src` зависит от CWD; скачивание изображений происходит как побочный эффект внутри `extract_links`; логгер настраивается на уровне модуля |
| `chm_prepare/to_chm_prepare.py` | трансформация `html_src/*.html` → `html_out/*.htm`, `qsp.hhc`, `qsp.hhk` | god-class `ChmPrepare`: настройки, чтение файлов, чистка страниц, ссылки, картинки, hhc, hhk в одном месте; настройки захардкожены в `__init__`; путь через `os.getcwd() + '..'`; голые `except`; print-отладка; эвристика нечёткого сопоставления имён изображений |
| `_auxtools/extract_keywords.py` | `html_out/qsp.hhk` + htm → `html_src/anchors.json` | независимый скрипт с собственным представлением формата anchors.json; хрупкая привязка якорей к номерам строк |
| `qsp_wiki_downloader/test_*.py` | «тесты» | это не pytest, а ручные сетевые сценарии; требуют реального wiki |

Дублирование между скриптами:
- helpers `read_file`/`json_load`/написание файлов — переписать в общий модуль;
- правила «безопасное имя файла из URL» — свои реализации в downloader;
- сопоставление URL ↔ локальный файл — размазано по downloader (создаёт схему),
  prepare (consumes `urls_links_to_files.json`), extract_keywords (consumes anchors).

## Контракты между этапами (данные, а не код)

Рефакторинг должен сохранить эти файловые контракты (форматы см. в `handoff.md`):

1. downloader → `html_src/*.html`, `html_src/images/*`, `html_src/urls_links_to_files.json`
2. (ручной/вики этап) → `html_src/sidebar.html`, `html_src/help_keywords.html`,
   `html_src/anchors.json` (создаётся/обновляется extract_keywords)
3. chm_prepare → `html_out/*.htm`, `html_out/qsp.hhc`, `html_out/qsp.hhk` (cp1251)
4. HTML Help Workshop → `.chm` (внешний инструмент, не автоматизируем)

## Целевая структура

```
qsp_help_builder/
├── __init__.py
├── config.py            # dataclass Settings, загружаемый из внешнего qsp_help.toml (единственный источник настроек); пути — от корня проекта
├── fs_utils.py          # read_text / write_text / load_json / save_json / safe_filename
├── schema.py            # модель urls_links_to_files.json (pages/images), загрузка-сохранение
├── download/
│   ├── __init__.py
│   ├── crawler.py       # обход по ссылкам (BFS), session, delay, статистика
│   └── naming.py        # URL -> имя html-файла / файла изображения (расширения из content-type)
├── prepare/
│   ├── __init__.py
│   ├── page_clean.py    # извлечение div.page.group, удаление toc/scripts/icoн-картинок, спец-правки start
│   ├── links.py         # replace_links / replace_href (чистая функция: soup-узел + схема)
│   ├── images.py        # extract_images / replace_src (чистая функция: узел + схема)
│   ├── hhc.py           # построение qsp.hhc из sidebar
│   └── hhk.py           # построение qsp.hhk из help_keywords + anchors
├── anchors.py           # единый формат anchors.json: извлечение (ex hhk) и вставка (в htm)
├── templates.py         # CHM_PAGE / HHC_PAGE / HHK_PAGE заготовки
├── pipeline.py          # run_download() / run_prepare() / run_anchors() — композиция этапов
└── cli.py               # argparse: download | prepare | anchors | all
tests/
├── fixtures/            # пара маленьких html-страниц DokuWiki + фиксированная схема
├── test_links.py        # чистые функции: замена ссылок по схеме
├── test_naming.py       # URL -> имена файлов
├── test_hhc_hhk.py      # генерация hhc/hhk на фикстурах
└── test_anchors.py      # извлечение/вставка якорей, обратная совместимость формата
```

Принципы:
- сетевой код (`download/`) отделён от трансформаций (`prepare/`, `anchors.py`) —
  prepare полностью офлайн-тестируем;
- функции, принимающие `Tag`/`BeautifulSoup` + данные схемы, вместо методов класса
  с 10 полями в `self`;
- все пути — `pathlib.Path` от корня пакета/проекта; CWD не влияет;
- настройки: единственный источник — `qsp_help.toml` в корне проекта (папки src/out,
  base_url, hhc/hhk имена, files_to_del, задержки/таймауты); `config.py` лишь
  типизирует, загружает и валидирует его (решение от 2026-10-16);
- `print`-отладка → `logging` с настраиваемым уровнем (не на уровне импорта модуля);
- обработка ошибок: без голых `except`; проблемные файлы логируются и collect-ся
  в итоговый отчёт этапа.

## Что сознательно НЕ делаем в этот рефакторинг

- Не автоматизируем компиляцию CHM (HTML Help Workshop — внешний exe).
- Не меняем форматы `urls_links_to_files.json` / `anchors.json` в смысле breaking change
  (можно расширять, старые файлы должны читаться).
- Не чиним качество данных вики (битые картинки и т.п.) — это контентные проблемы.

## Направление после рефакторинга: одностраничник / PWA

Заявленная цель (после стабильной сборки в CHM): автономный одностраничный HTML
или PWA-приложение. Вывод сессии: **выбор не бинарный** — оба варианта это разные
«обёртки» над одной моделью контента; эффективность = сначала сделать модель,
потом рендереры.

### Сравнение (для нашей аудитории и способа распространения)

| Критерий | Одностраничник | PWA |
|---|---|---|
| Дистрибуция | один .html, двойной клик с file:// (как CHM) | нужен https-хостинг, SW не работает с file:// |
| Офлайн | полный сразу | после первого визита |
| Размер | текст ~OK; base64-картинки — десятки МБ; нет инкрементальных обновлений | ленивые картинки, обновления без перевыдачи |
| Поиск | Ctrl+F (плюс простой JS-индекс поверх модели) | полнотекстовый client-side (minisearch/lunr) |
| Мобильные | плохо | installable, responsive |
| Сложность сборки | чистый Python | манифест + SW + инвалидация кэша + JS |
| Соответствие README | автор хотел именно это («справка в виде одностраничного html») | замещающий онлайн-справочник вместо ссылки на вики |

### Рекомендуемый порядок

1. **Стадия «модель сайта»** (додаётся в пайплайн на Фазах 3–5): нейтральный JSON —
   страницы `{slug, title, html-фрагмент, якоря}`, граф внутренних ссылок,
   разрешённый в slugs (не в .htm-файлы), манифест изображений.
   `qsp.hhc`/`qsp.hhk` становятся рендерером модели для CHM — единый источник истины
   для всех целей.
2. **Одностраничник — первый рендерер** модели: проверка модели без инфраструктуры,
   знакомый аудитории формат файла. Навигация — hash-router на встроенном JS,
   ссылки `#slug`, якоря `#slug~anchor`.
3. **PWA — второй рендерер** той же модели для хостинга (GitHub Pages): статический
   сайт + manifest.json + service worker + индекс поиска. Это же закрывает мечту
   «онлайн-версия справки» из страницы start.

Дополнение к целевой структуре (после Фаза 5, новыми фазами 7–8):

```
qsp_help_builder/
├── model.py             # сборка модели сайта из подготовленных фрагментов
├── render/
│   ├── chm.py           # текущий выход (htm + hhc/hhk) — переезжает из prepare/
│   ├── spa.py           # одностраничник: модель -> index.html + папка images/ рядом (гибрид, без base64)
│   └── pwa/             # статика + manifest + sw.js + search index (minisearch)
```

**Предварительные условия** (иначе оба направления буксуют):
- чинить ассет-пайплайн загрузчика (backlog handoff §4.2: срез query-строки,
  неверные имена картинок) — одностраничнику нужны корректные inline-ресурсы;
- якоря как стабильные id (backlog §4.4), а не номера строк — от них зависит
  hash-навигация и PWA.

**Критерий окончательного выбора**, если всё-таки что-то одно:
нужен *файл* (раздача как CHM) — одностраничник; нужен *всегда актуальный
справочник* в браузере/телефоне — PWA.

## Принятые решения (2026-10-16, закрыли «открытые вопросы»)

1. **Имя пакета**: `qsp_help_builder` — без изменений.
2. **Настройки**: только внешний `qsp_help.toml` в корне проекта; `config.py` —
   dataclass-модель + загрузчик/валидатор, без значений by-default в коде.
   Файл обязателен для запуска; в репозитории хранится рабочая версия.
3. **Старые папки**: `qsp_wiki_downloader/` и `chm_prepare/` удаляются сразу
