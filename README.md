# Сборщик справки из wiki.qsp.org

Проект собран в Python-пакет `qsp_help_builder` с единой точкой входа. Команды запускаются
из корня проекта (там, где лежит пакет). В отличие от старых скриптов, рабочие пути
берутся из `qsp_help.toml`, а не из текущей директории, — результат сборки не зависит от CWD:

```
python -m qsp_help_builder download    # этап 1: выгрузка страниц и картинок с wiki (нужна сеть)
python -m qsp_help_builder prepare     # этап 2: подготовка html_src -> html_out (+ qsp.hhc/qsp.hhk)
python -m qsp_help_builder anchors     # этап 2b: извлечение якорей из собранного html_out в anchors.json
python -m qsp_help_builder all         # download -> prepare -> anchors одной командой
python -m qsp_help_builder spa         # одностраничник: html_src -> spa_out/index.html (+ images/)
```

Команды `download`/`prepare`/`anchors`/`all` собирают CHM — этот путь не изменился.
`spa` — отдельный выход (полностью офлайн, сеть не трогает): из тех же `html_src`
строит автономный одностраничный `spa_out/index.html` с hash-навигацией и локальной
папкой `images/`. Каталог вывода задаётся в `[spa].out`, а первая страница (которую
hash-навигация показывает без хеша) — в `[spa].start_page` файла `qsp_help.toml`.

Настройки (папки src/out/images, base_url, кодировки, исключаемые разделы, уровень
лога) — единственные и только в [`qsp_help.toml`](qsp_help.toml). Файл обязателен:
значений по умолчанию в коде нет.

Зависимости: `pip install -r requirements.txt` (requests, beautifulsoup4, lxml).

## Этапы сборки

1. Выгрузка исходных html-файлов с [wiki.qsp.org](https://wiki.qsp.org) — `download`.
2. Подготовка файлов к формату `chm` — `prepare` (+ `anchors`).
3. Сборка `chm` программой **HTML Help Workshop** — внешний инструмент, не автоматизирован.

## Первый этап. Выгрузка страниц (`download`)

1. `python -m qsp_help_builder download` — выгрузит все страницы справки и изображения.
   Изображения DokuWiki (`lib/exe/fetch.php?media=…`) сохраняются под корректными
   именами: base-имя берётся из значения `media` (`namespace:file` → `namespace_file`),
   а не схлопывается в одно `fetch.png`.
2. Страницы и изображения сохранятся в `html_src` (картинки — в `html_src/images`).
3. Там же появится `urls_links_to_files.json` — связка прямых url ↔ файлов.
4. **Перемещать и удалять эти файлы нельзя!!!**

> **Ре-краул и baseline.** `download` перезаписывает `html_src` целиком: вики
> отдаёт per-request токены (`sec`/`tok`/`rev`), поэтому байты исходников меняются
> при каждом скачивании — это ожидаемо. Действующий зафиксированный снимок
> состояния — [`_baseline/2026-10-17/BASELINE.md`](_baseline/2026-10-17/BASELINE.md);
> проверки приёмки — через `python _baseline/make_manifest.py` (SHA256-манифесты
> `html_src`/`html_out`). Старый `_baseline/2026-10-16/` оставлен как история.

## Второй этап. Подготовка страниц (`prepare`)

1. `python -m qsp_help_builder prepare` — возьмёт скачанные файлы и подготовит к сборке.
2. Подготовленные файлы пересохранятся в `html_out` (кодировка страниц utf-8,
   `qsp.hhc`/`qsp.hhk` — windows-1251 по требованию HTML Help Workshop).
3. В `html_out` появятся `qsp.hhc` (содержание) и `qsp.hhk` (указатель).
4. Автоматически выполняются: исключение разделов навигатора/aqsp из `files` в
   `qsp_help.toml`, чистка ссылок и картинок, снятие «кликабельности» с изображений,
   удаление изображений-иконок, правки стартовой страницы, лог и ссылка на живую вики.
5. Точечные правки указателя (`qsp.hhk`) задаются в коде, а не вручную: раздел
   `[chm.keyword_overrides]` в `qsp_help.toml` (title → `file.htm#anchor`) переопределяет
   автоматическую карту якорей. Ассеты картинок в `html_out` (`qgen.png` и др.)
   укладываются в папку вручную — `prepare` их не копирует.
6. Якоря переживают пересборку через `anchors.json`: `prepare` вставляет их из
   `html_src/anchors.json` (согласованный 0-based индекс строки), а `python -m qsp_help_builder
   anchors` извлекает актуальные якоря обратно из собранного `html_out` (цикл замкнут;
   после ре-краула сходится до идемпотентной точки покоя за 2–3 итерации).

## Третий этап. Сборка справки

1. Потребуется [HTML Help Workshop](https://www.helpandmanual.com/downloads_mscomp.html) —
   установщик в папке `help_workshop`.
2. Инструкция по созданию проекта скопирована в `help_workshop` (в виде md).
3. Создаёте новый проект, добавляете нужные файлы (не забудьте отметить `Default file`),
   запускаете компиляцию.
4. Внимательно читайте ошибки компиляции.

## Что дальше?

- Распространяете полученный `chm` среди жильцов вашего ЖэКа;
- **одностраничник уже доступен**: `python -m qsp_help_builder spa` → автономный
  `spa_out/index.html` (открывается двойным кликом с `file://`, hash-навигация,
  картинки в `spa_out/images/`). Модель сайта общая для CHM и SPA — ссылки готовит
  один и тот же модуль `prepare`, просто под разные целевые профили;
- идёт работа над PWA (`render/pwa`: manifest + service worker + client-side поиск,
  единый ассет-пайплайн для `url()` в CSS) — см. `plan.md`, Фаза 8.
